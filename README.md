# Пульт маркетинга детских праздников

Платформа собирает в одну базу Яндекс Директ, Яндекс Метрику, Callibri, Битрикс24, Топвизор и заявки с сайта. Она считает цену заявки и брони по каждой кампании и площадке. Каждое утро платформа чистит РСЯ по правилам, а в 9:00 присылает отчёт в Telegram с кнопками «Применить» и «Отклонить».

```
Источники (API, каждое утро) ─► База (PostgreSQL) ─► Дашборд
                                       │
                                       ├─► Модуль правил ─► мелкие правки сразу ─► Директ API (журнал, откат)
                                       │                └─► крупные ─► Telegram «да» ─┘
                                       └─► ИИ-модуль (необязательно, только обезличенные цифры) ─► отчёт
```

## Проекты

Платформа многопроектная. На главной странице — список проектов, кабинет проекта открывается по адресу
`/p/<проект>/`. У каждого проекта своя база (SQLite-файл `projects/<проект>.db` рядом с основной базой
или схема `p_<проект>` в PostgreSQL) и свои подключения: их задают во вкладке «Подключения» кабинета,
кнопка «Проверить» делает один лёгкий запрос к сервису. Ключи хранятся в базе зашифрованными ключом
`PLATFORM_SECRET_KEY` (или файлом `secrets/platform.key`, который создаётся сам). Потеряете ключ —
ключи проектов придётся ввести заново.

В `.env` остаются общие настройки: база, логин и пароль дашборда, часовой пояс и валюта по умолчанию.
Значения из `.env` действуют во всех проектах, пока проект не задал своё.

```bash
python -m partyhub projects create "Crazy Drift"            # новый проект (или кнопкой на главной)
python -m partyhub projects create "Crazy Drift" --from-env # перенести в проект ключи, заполненные в .env
python -m partyhub projects                                 # список
python -m partyhub -p crazy-drift check                     # любая команда — в проекте
```

Планировщик сам обходит все проекты. Заявки с сайта и из Tilda принимаются по адресам из вкладки
«Подключения» (`/p/<проект>/api/webhooks/form` и `/tilda`). Брони YCLIENTS склеиваются с заявками
по телефону, и на «Сводке» видно, сколько броней пришло из Директа, из других источников и без источника.

## Быстрый старт на демо-данных

Нужен Docker.

```bash
cp .env.example .env            # задайте DASHBOARD_PASSWORD и WEBHOOK_TOKEN
docker compose up -d --build
docker compose exec app python -m partyhub demo --yes
```

Откройте http://localhost:8000 и войдите с логином и паролем из `.env`. Демо — это 90 дней вымышленного детского центра в Ереване. Последние две недели в нём прогнаны настоящими правилами платформы.

Без Docker (Python 3.11+):

```bash
pip install -r requirements.txt
echo "DATABASE_URL=sqlite:///partyhub.db" > .env && echo "DASHBOARD_PASSWORD=demo" >> .env
python -m partyhub demo --yes
python -m partyhub serve        # http://localhost:8000
```

## Подключение источников

Все ключи хранятся в `.env`. Источник без ключей просто пропускается, и в дашборде он помечен как «не подключён».

| Источник | Что указать в `.env` | Где взять |
| --- | --- | --- |
| Яндекс Директ | `DIRECT_TOKEN`, `DIRECT_CLIENT_LOGIN` (только для агентских аккаунтов) | Зарегистрируйте приложение в Яндекс OAuth с доступом к Директу и подайте [заявку на доступ к API](https://yandex.ru/dev/direct/doc/ru/access-request). Затем владелец кабинета выдаёт приложению OAuth-токен. |
| Яндекс Метрика | `METRIKA_TOKEN`, `METRIKA_COUNTER_ID`, `METRIKA_GOAL_ID` | Тот же OAuth с правами на Метрику. Номер счётчика — в Метрике, номер цели «заявка» — в настройках целей. |
| Callibri | `CALLIBRI_EMAIL`, `CALLIBRI_TOKEN`, `CALLIBRI_SITE_ID` | Профиль → «Получить доступ к API». Нужны права «Аналитика» и «Настройка», токен приходит на почту. [Документация](https://callibri.ru/help/api_webhook/kak_vospolzovatsya_api) |
| Битрикс24 | `BITRIX_WEBHOOK_URL`, поля даты праздника и числа детей, `BITRIX_CHAT_ID` | Разработчикам → Другое → Входящий вебхук, права `crm`, `user`, `im`. Коды полей начинаются с `UF_CRM_`. Вебхук создаёт сотрудник, который состоит в чате с заявками. |
| Топвизор | `TOPVISOR_USER_ID`, `TOPVISOR_API_KEY`, `TOPVISOR_PROJECT_ID`, `TOPVISOR_REGION_INDEX` | Профиль → API. Проектов и регионов можно указать несколько через запятую; пустой `TOPVISOR_REGION_INDEX` — все регионы проекта. Список ID: `python -m partyhub topvisor-projects`. |
| Формы сайта | `WEBHOOK_TOKEN` | Форма отправляет POST на `/api/webhooks/form?token=…`. Пример — в `examples/site-form.js`. |
| Telegram | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_LEADS_CHAT_ID` | Создайте бота через @BotFather и добавьте его в рабочий чат и в чат с заявками. Есть публичный HTTPS-адрес — `python -m partyhub telegram-webhook`; нет — `python -m partyhub telegram-poll`. |
| Google-таблица | `GOOGLE_SERVICE_ACCOUNT_FILE`, `GOOGLE_SHEET_ID`, `GOOGLE_SHEET_TAB` | См. «Заявки из чатов и Google-таблица» ниже. |

После подключения проверьте ключи: `python -m partyhub check` — каждый источник делает один лёгкий запрос
и пишет, что не так. Затем загрузите историю: `python -m partyhub collect --from 2026-07-01`.

### Заявки из чатов и Google-таблица

Все заявки после склейки по телефону попадают в Google-таблицу: дата заявки, телефон, имя клиента, источник,
UTM-метка, комментарий и служебный столбец ID (его можно скрыть, но не удалять). Новые заявки добавляются
внизу, у известных дописываются только пустые ячейки имени, источника и UTM. Дату, телефон и комментарий
платформа после создания строки не трогает. Планировщик обновляет таблицу каждые `LEADS_SYNC_MINUTES` минут.

**Google-таблица.**

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект и включите Google Sheets API.
2. IAM и администрирование → Сервисные аккаунты → создайте аккаунт, на вкладке «Ключи» добавьте ключ JSON.
3. Положите файл в папку `secrets/` рядом с `docker-compose.yml` как `google-service-account.json`.
4. Создайте таблицу и откройте доступ на почту сервисного аккаунта (`…@….iam.gserviceaccount.com`) с правом «Редактор».
5. В `.env` укажите `GOOGLE_SHEET_ID` из ссылки `docs.google.com/spreadsheets/d/<ID>/edit`.
6. `python -m partyhub sheets-sync` — первая выгрузка. Лист «Заявки» создастся сам.

**Telegram.** Бот читает чат с заявками и разбирает сообщения: телефон, имя, UTM-метки, текст — в комментарий.
Обычная переписка без телефона и полей заявки пропускается.

1. Добавьте бота в чат с заявками. В @BotFather выключите ему `/setprivacy` (или сделайте администратором) —
   иначе в группе он видит только команды.
2. Напишите в чате любое сообщение и выполните `python -m partyhub telegram-chats` — ID чата впишите в `TELEGRAM_LEADS_CHAT_ID`.
3. Без публичного адреса запустите `docker compose --profile telegram up -d` (или `python -m partyhub telegram-poll`).
   С адресом — `python -m partyhub telegram-webhook`, сообщения придут на `/api/telegram`. Работает один способ из двух.

Бот видит только сообщения, пришедшие после его добавления: старые заявки из Telegram не подтянутся.

**Чат Битрикс24.** `python -m partyhub bitrix-chats` покажет последние чаты сотрудника, создавшего вебхук.
ID нужного (`chat123`) впишите в `BITRIX_CHAT_ID`. История за период: `python -m partyhub collect --only bitrix_chat --from 2026-10-01`.

Шаблоны уведомлений разбираются по полям «Имя:», «Телефон:», «Комментарий:», `utm_source:` и по UTM-меткам в ссылках.
Как поступать с сообщениями без телефона — `rules.yaml → chats`, что класть в комментарий — `rules.yaml → sheets`.

### Разметка ссылок в Директе

Без меток платформа не поймёт, с какой площадки пришла заявка. Добавьте в ссылки всех объявлений:

```
utm_source=yandex&utm_medium=cpc&utm_campaign={campaign_id}&utm_content={source_type}|{source}&utm_term={keyword}
```

Включите эту же разметку в Callibri, чтобы звонки тоже получали площадку.

## Как работает ежедневный цикл

Планировщик (`docker compose` поднимает его сам) запускает два задания:

1. **06:00 — `daily`.** Собирает данные за вчера: 3 дня назад для рекламы и 45 дней для CRM, потому что статусы броней меняются. Затем склеивает звонки, формы и чаты в заявки по телефону, оценивает правки недельной давности, прогоняет правила и отправляет новые брони в Метрику как офлайн-конверсии.
2. **09:00 — `report`.** Отправляет отчёт в Telegram: цифры за вчера, что сделано, что ждёт решения, эффект правок, ошибки источников.

Правки делятся на три уровня. Уровень каждого правила задаётся в `config/rules.yaml`.

| Уровень | Что сюда входит по умолчанию | Как применяется |
| --- | --- | --- |
| `auto` | Площадка потратила 1,5 целевой цены заявки без заявок; приложение с CTR выше 3% без заявок; минус-слова из списка стоп-слов | Сразу, не больше 30 правок в день, с записью в журнал |
| `approval` | Площадка с отказами выше 70% на 30+ визитах | После «Применить» в Telegram или в дашборде |
| `alert` | Расход за день в 1,5 раза выше среднего за неделю | Только сигнал в отчёте |

Платформа не трогает площадки, которые хоть раз дали бронь, и площадки из списка `protected_placements`. Отклонённую правку она не предлагает повторно 30 дней. Через 7 дней каждая правка оценивается по цене заявки до и после, и её можно откатить одной кнопкой.

### Режимы работы с Директом (`DIRECT_MODE`)

- `dry_run` — правки только записываются в журнал. Режим по умолчанию: начните с него и посмотрите, что платформа предлагает.
- `sandbox` — правки уходят в [песочницу API](https://yandex.ru/dev/direct/doc/ru/concepts/sandbox), реальный кабинет не меняется.
- `live` — правки уходят в боевой кабинет.

Первые 2–4 недели с новым клиентом держите правила в `dry_run` и подбирайте пороги в `rules.yaml` под его цифры. Правки из `dry_run` в Директ не уходили, поэтому после перехода в `live` платформа предложит их снова и применит по обычным правилам.

Защита от ошибок:

- если Callibri или Битрикс24 утром не обновились, автоправки не выполняются, а уходят на одобрение — без свежих заявок хорошая площадка выглядит пустой;
- после каждой правки платформа перечитывает кампанию и проверяет, что изменение действительно появилось;
- откат убирает площадку или слово только из тех кампаний, где их добавила платформа;
- все записи в Директ идут строго по одной, даже если правку одобряют одновременно из Telegram и дашборда.

## Вкладка «Директ»

Отдельная вкладка дашборда со всеми инструментами по работе с кабинетом. Сверху — фильтр по типу кампаний
(поиск, РСЯ, автотаргетинг, ЕПК) и выбор нейросети.

| Группа | Инструмент | Что делает | Какие правки предлагает |
| --- | --- | --- | --- |
| Чистка | Чистка площадок | Площадки РСЯ по правилам из `rules` | Исключить площадку |
| Чистка | Чистка запросов | Разбирает поисковые запросы на слова: расход, клики, конверсии | Минус-слово (стоп-слова и дорогие слова без конверсий; слова из ваших ключей — никогда) |
| Чистка | Автотаргетинг | Запросы автотаргетинга, доля в расходе, разбивка по категориям | Минус-фраза; кандидаты в ключи — подсветкой |
| Конверсии | Конверсии кампаний | Клик → заявка → бронь, цена заявки и брони против цели, изменение к прошлому периоду, заявки без меток | Сигналы: расход без заявок, просадка конверсии |
| Ставки | Целевая цена конверсии | Факт цены брони (или заявки) против цели | Поменять целевую цену в стратегии, не больше ±20% за раз |
| Ставки | Корректировки ставок | Цена конверсии по устройствам и полу × возрасту | Корректировка −30…+30% за раз |
| ИИ | ИИ-аудит | Нейросеть смотрит выводы всех инструментов | Любые из правок выше — после проверки платформой |

Внизу вкладки можно задать нейросети вопрос по данным кабинета.

**Безопасность.** Кнопка «В журнал на одобрение» кладёт правки в журнал со статусом «ждёт решения». Корректировки,
целевая цена и советы ИИ применяются только после «Применить» в журнале или в Telegram — в текущем режиме
`DIRECT_MODE`, с проверкой результата и откатом к прежнему значению. Правка целевой цены не применится, если цену
поменяли в кабинете после предложения. ИИ получает только обезличенные цифры; каждую его рекомендацию платформа
сверяет с данными (кампания и площадка существуют, корректировка в допустимых пределах).

**Данные.** Для запросов, автотаргетинга и корректировок сборщик Директа дополнительно забирает разметку запросов
(`CriterionType`, `TargetingCategory`) и срезы по устройствам и демографии. Конверсии в них считаются по целям из
`DIRECT_GOAL_IDS` — без них инструменты показывают расход, но не предлагают правок по конверсиям. Названия полей
отчётов сверьте в песочнице: если Директ не примет поля разметки, запросы соберутся без неё.

**Настройки** — в `config/rules.yaml`, раздел `direct_tools`: пороги каждого инструмента, `enabled` (показывать ли),
`daily` (запускать ли в утреннем цикле; по умолчанию — только сигналы по конверсиям).

Из командной строки: `python -m partyhub direct` (список), `python -m partyhub direct bids --days 30 --propose`.

### Как добавить инструмент

Новый файл в `partyhub/direct/tools/` — вкладка подхватит его сама, правка HTML не нужна:

```python
from ..registry import Col, DirectTool, ToolContext, ToolResult, register

@register
class MyTool(DirectTool):
    id, title, group = "my_tool", "Мой инструмент", "Чистка"
    description = "Что делает."
    campaign_types = ("search",)                     # для фильтра вкладки
    columns = [Col("campaign", "Кампания"), Col("cost", "Расход", "money")]

    def run(self, ctx: ToolContext) -> ToolResult:   # ctx.session, ctx.d1, ctx.d2, self.config()
        return ToolResult(rows=[...], proposals=[...], summary=[...], notes=[...])
```

Новый тип правки в Директе — класс с `apply`/`rollback`/`describe` в `partyhub/direct/kinds.py`.

### Нейросети

Провайдеры — в `partyhub/ai/providers.py`: GPT (OpenAI), Gemini, Claude, YandexGPT. Ключи и модели — в `.env`
(`OPENAI_API_KEY`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, `YANDEXGPT_API_KEY`…), во вкладке модель переключается
списком. `OPENAI_BASE_URL` подключает любой совместимый с OpenAI сервис (OpenRouter, DeepSeek, локальную модель)
без нового кода. Другую модель можно добавить одним классом с `@register`. Модели по умолчанию
(`gpt-5-mini`, `gemini-2.5-flash`) сверьте с актуальным списком у провайдера.

### ИИ-агент

Во вкладке «Директ» есть окно агента. Ему дают задание словами: «создай поисковую кампанию на дни рождения в Ереване,
5 000 в день», «сделай отчёт по кампаниям за 30 дней», «найди, где сливается бюджет, и подготовь чистку».
Агент сам читает кабинет (кампании, группы, ключи, объявления, отчёты Директа, справочник регионов) и цифры платформы
(заявки и брони из CRM), рисует таблицы и собирает **план изменений**. Можно отвечать ему и уточнять план.

Кабинет меняется только после кнопки «Применить план». До этого агент ничего не пишет в Директ.

- Что умеет план: создать кампанию целиком (стратегия, бюджет, минус-слова, группы с регионами, ключи, объявления,
  быстрые ссылки), изменить кампанию (название, бюджет, минус-слова, исключённые площадки), остановить или запустить
  кампании, объявления и фразы, добавить фразы и объявления, поменять ставки, отправить на модерацию.
- Новые кампании создаются черновиками и на модерацию не уходят, если об этом не попросить.
- Перед применением каждая операция проверяется ещё раз: длина текстов объявлений, лимиты бюджета и ставок, защищённые
  кампании. Лимиты — в `config/rules.yaml` → `direct_agent` (`max_daily_budget`, `max_bid`, `max_ops`,
  `allow_moderation`, `protected_campaign_ids`). Там же `site_url` и тип новых кампаний (`UNIFIED_CAMPAIGN` — ЕПК,
  или `TEXT_CAMPAIGN`).
- Применённый план можно откатить: созданные кампании удаляются (или останавливаются, если уже показывались),
  изменённые поля возвращаются к прежним значениям.
- Режим берётся из `DIRECT_MODE`: в `dry_run` план только отмечается применённым, в `sandbox` пишет в песочницу,
  в `live` — в боевой кабинет.

Агент работает с GPT, Gemini и Claude через встроенный вызов функций, с YandexGPT — через JSON-протокол. Новая операция
плана — класс с `@op` в `partyhub/direct/changeset.py`, новая функция чтения — метод `t_<имя>` в `partyhub/direct/agent.py`
и её описание в `_tools()`.

API: `POST /api/direct/agent` (`{"task", "provider"}`), `POST /api/direct/agent/{id}/reply`, `GET /api/direct/agent/{id}`,
`POST /api/direct/changesets/{id}/apply|reject|rollback`.

## Команды

```bash
python -m partyhub daily              # утренний цикл вручную
python -m partyhub report --print     # показать отчёт, не отправляя
python -m partyhub collect --only direct,metrika --from 2026-10-01
python -m partyhub rules --day 2026-10-20
python -m partyhub direct-check       # проверить токен Директа
python -m partyhub check              # проверить ключи Метрики, Callibri, Битрикс24, Telegram, Google-таблицы, Топвизора
python -m partyhub topvisor-projects  # проекты и индексы регионов Топвизора
python -m partyhub leads-sync         # свежие заявки → склейка → Google-таблица (планировщик делает это сам)
python -m partyhub sheets-sync --from 2026-10-01   # выгрузить заявки в таблицу за период
python -m partyhub upload-conversions # отправить брони в Метрику
python -m partyhub export --out export --days 30   # JSON для DataLens и других дашбордов
python -m partyhub direct bids --propose   # инструмент вкладки «Директ», предложения — в журнал
```

## Данные и безопасность

- Телефоны и имена клиентов хранятся в вашей базе и в Google-таблице заявок. В дашборде телефоны скрыты. Таблицу открывайте только конкретным людям, без доступа «по ссылке». Текст из чатов, похожий на формулу, записывается в таблицу как текст.
- ИИ-модуль выключен по умолчанию (`AI_PROVIDER=template`). Если его включить, он получает только обезличенные цифры: расходы, клики, площадки, кампании. ИИ-агент Директа дополнительно видит структуру кабинета: названия кампаний, ключевые фразы, тексты объявлений. Телефоны и имена клиентов агенту не передаются. Выбирая провайдера, проверьте, что ваша страна и компания входят в список, где он работает.
- Дашборд закрыт логином и паролем. Пока в `.env` не заданы `DASHBOARD_PASSWORD`, `WEBHOOK_TOKEN` и `TELEGRAM_WEBHOOK_SECRET` (не короче 6 символов), соответствующие части платформы не работают.
- Заявки с сайта лучше отправлять с сервера сайта, чтобы токен не был виден посетителям. С одного адреса принимается не больше 20 заявок за 10 минут. Для доступа из интернета включите HTTPS: укажите свой домен в `Caddyfile` и запустите `docker compose --profile https up -d`.
- Требования к хранению персональных данных зависят от страны клиента. Уточните их у юриста до подключения живых данных.

## Что проверено и что сверить при подключении

Проверено: 111 автотестов с подменой всех API, полный демо-прогон на SQLite и PostgreSQL 16, интерфейс в браузере на ширине телефона и ноутбука, в светлой и тёмной теме.

На живых API платформа ещё не запускалась, сборку Docker-образа тоже стоит проверить на сервере. При первом подключении сверьте с документацией:

- **Callibri** — базовый адрес API и имена параметров авторизации. Они приходят в письме вместе с токеном; адрес меняется через `CALLIBRI_BASE_URL`.
- **Топвизор** — формат ответов `projects_2/projects` (поисковики и регионы) и `positions_2/history` (поле `group_name`, постраничная выдача через `limit`/`offset`). Разбор вынесен в `region_names` и `parse_history`.
- **Метрика** — срок, за который она принимает офлайн-конверсии (`offline_conversions.max_age_days`).
- **Директ** — потолок списка исключённых площадок (`limits.max_excluded_sites`). Кампании читаются и меняются через адрес API `v501` (он нужен для Единой перфоманс-кампании), отчёты — через `v5`. Первый запуск сделайте в режиме `sandbox`. Для агента в песочнице отдельно проверьте создание ЕПК: формат стратегий и быстрых ссылок.
- **Битрикс24** — коды статусов в ваших воронках. Сопоставление задаётся в `crm_status_map`.

## Структура

```
partyhub/
  collectors/   сборщики: direct, metrika, callibri, bitrix, topvisor
  pipeline/     нормализация, склейка заявок, расчёт показателей
  rules/        правила и применение правок (журнал, откат, оценка)
  reports/      ежедневный отчёт и Telegram
  ai/           нейросети: providers.py (GPT, Gemini, Claude, YandexGPT) и наблюдения в отчёте
  direct/       вкладка «Директ»: tools/ — инструменты, kinds.py — правки ставок, service.py — запуск
  web/          FastAPI, API и дашборд (ui/ — исходники, в т. ч. direct.html; static/ — собранный)
  demo.py       генератор демо-данных
config/rules.yaml   пороги, уровни правил, статусы CRM
tests/              автотесты: python -m pytest
```

Дашборд собирается из `partyhub/web/ui` командой `python tools/build_ui.py`. Та же разметка используется в онлайн-прототипе.
